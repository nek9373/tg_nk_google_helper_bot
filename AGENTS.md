# Инструменты этого репозитория

Здесь живёт доступ к Google-аккаунтам Никиты и воркер, который следит за
входящей почтой. Если ты отвечаешь на его вопрос про письма, календарь,
диск или YouTube — работать нужно отсюда.

## Первое действие — всегда `list`

```bash
python3 gmail_tool.py list
```

Он показывает подключённые ящики, **какие сервисы доступны у каждого** и
назначение. Права у ящиков РАЗНЫЕ: один может иметь полный доступ к
YouTube и диску, другой — только чтение почты. Не помня этого, легко
пообещать то, чего инструмент не может, или полезть в личную почту с
рабочим вопросом.

Назначение ящика («личная», «рабочая, проект X») тоже в `list`. Если у
ящика оно пустое — спроси Никиту, а не угадывай по домену.

## Почта

```bash
python3 gmail_tool.py search <адрес> "is:unread" -n 10 --snippet
python3 gmail_tool.py read <адрес> <id>
python3 gmail_tool.py draft <адрес> --to a@b.c --subject "Тема" --body -
python3 gmail_tool.py send <адрес> --to a@b.c --subject "Т" --body - --yes
```

Синтаксис запросов — как в веб-интерфейсе Gmail: `from:`, `newer_than:2d`,
`has:attachment`, `is:important`.

**Про отправку.** Даже там, где право выдано, `send` требует явного
`--yes`. Это намеренно: письмо не отзывается, а ошибка агента не видна
никому, пока адресат не ответит. По умолчанию делай `draft` и скажи
Никите, что черновик готов — отправит он сам. Слать сам только если он
прямо попросил отправить.

## YouTube, календарь, диск

Права выданы там, где `list` показывает соответствующий сервис. Готовых
обёрток пока нет — работать через `googleapiclient` с теми же токенами:

```python
import sys; sys.path.insert(0, '/home/nklyuchnikov/PycharmProjects/tg_nk_google_helper_bot')
import gmail_tool as gt
from googleapiclient.discovery import build

creds = gt._load_creds('business@ddinsights.org')
yt = build('youtube', 'v3', credentials=creds, cache_discovery=False)
cal = build('calendar', 'v3', credentials=creds, cache_discovery=False)
drive = build('drive', 'v3', credentials=creds, cache_discovery=False)
```

**Заливка видео упрётся в ограничение YouTube, и это не наша поломка.**
У непроверенного проекта ролики, загруженные через API, принудительно
остаются private, и опубликовать их нельзя, пока проект не пройдёт
compliance audit. Всё остальное — метаданные, описания, теги, превью,
плейлисты, комментарии, аналитика — работает штатно. Если Никита просит
залить и опубликовать, скажи про это ограничение сразу, не выясняй
постфактум.

## Воркер входящей почты

```bash
python3 mail_watch.py status      # какие ящики под наблюдением
python3 mail_watch.py once        # прогнать проход руками
python3 mail_watch.py queue       # что Никита спрашивал у бота
```

Крутится как systemd-юнит `mail-watch`, опрашивает ящики раз в две минуты
и шлёт важное в бот `@nk_google_helper_bot`. Логи: `journalctl --user -u
mail-watch`.

## Чего делать нельзя

**Не пересказывать содержимое писем в общий контур.** Текст твоего ответа
уходит подсознанию и четырём помощникам — grok (xAI), qwen (Alibaba),
deepseek, gemini (Google), — и ложится в `chat_history` и RAG-индекс.
Процитированное письмо уедет к сторонним провайдерам и осядет в поиске по
памяти. Пересказывай суть, дословно — только необходимое, и никогда
целиком переписку, реквизиты, коды подтверждения, ссылки для входа.

**Не трогать файлы токенов руками.** Они в `~/.config/agent_gmail/tokens/`.
Всё, что нужно, делают команды `gmail_tool.py`.

**Не переподключать ящики самому.** `add` открывает браузер и требует
живого человека. Если доступ отвалился — скажи Никите, он переподключит.

## Если ящик перестал отвечать

Скорее всего протух OAuth-токен: пока consent screen в режиме Testing,
refresh token живёт 7 дней. Это не поломка кода и чинится одной командой,
которую выполняет Никита:

```bash
python3 gmail_tool.py add <адрес> --force
```

Не изобретай обходные пути и не молчи — сообщи ему.
